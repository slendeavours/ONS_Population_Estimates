## What is loaded, and what the columns mean

The dataset "provides Census 2021 estimates that classify households in England and Wales by tenure" (its metadata text, read from the held definition). A count is a number of households. The nine categories are the dataset's own tenure classification (`C2021_TENURE_9`), looked up by exact name in its codelist (codes 0 to 8):

| Column in `la_tenure_2021` | The publisher's category (code) |
|---|---|
| `total_households` | Total: All households (0). **The publisher's own total** |
| `owned_outright` | Owned: Owns outright (1) |
| `owned_mortgage` | Owned: Owns with a mortgage or loan (2) |
| `shared_ownership` | Shared ownership: Shared ownership (3) |
| `social_rented_council` | Social rented: Rents from council or Local Authority (4) |
| `social_rented_other` | Social rented: Other social rented (5) |
| `private_rented_landlord` | Private rented: Private landlord or letting agency (6) |
| `private_rented_other` | Private rented: Other private rented (7) |
| `lives_rent_free` | Lives rent free (8) |
| `social_rented_total`, `private_rented_total` | **Generated by the database** from their two parts (`social_rented_council + social_rented_other`, `private_rented_landlord + private_rented_other`). Not published figures; never written by the loader |
| `census_year` | 2021 |
| `source`, `loaded_at` | Provenance. `source` has two variants (below) and is not compared |

The dataset's metadata names the categories and does not define them further (for example what "Other social rented" or "Lives rent free" cover); ONS's census definition pages were not read for this note, so no wider definition is stated here. The measure loaded is `measures=20100`, which NOMIS's measures codelist names "value" (the other, 20301, is "percent").

**Disclosure control** (the dataset's metadata, "Protecting personal data"): Census 2021 swapped records (targeted record swapping) and added small changes to some counts (cell key perturbation), which "might make small differences between tables".

**The sums.** The eight parts sum to the publisher's total on all 296 authorities, in the held reply and in the live table, with no negative count.

## Discovery

`load` searches NOMIS for `*TS054*` (`.../dataset/def.sdmx.json?search=*TS054*`), which must list the declared dataset under its declared id, name and mnemonic; a TS054 dataset that is not declared (a new census) halts, naming what was seen. It then reads the dataset definition and the category codelist and downloads the data CSV for the latest date at geography type `TYPE424` to `data/raw/s3b_tenure/` under a dated name (git-ignored; a preview downloads too and writes nothing to the database). `--file CSV --def JSON` takes local copies. A download never overwrites a same-named file with different content (the definition's bytes differ on every download, because it carries the time it was prepared, so each is kept under its own hash).

## Source identity (rule 3), on every path

- **The dataset definition:** id `NM_2072_1`, name "TS054 - Tenure", mnemonic `c2021ts054`, FirstReleased and LastUpdated. **LastUpdated is the rank**, never a file name or a download date. Any other dataset halts.
- **The category codes**, looked up by exact name from the dataset's own codelist and never assumed. The codelist also holds six derived aggregates (`isDerived`, with children): 1001 Owned, 1002 Shared ownership, 1003 Social rented, 1004 Private rented, 9996 "Owns with a mortgage or loan or shared ownership" and 9997 "Private rented or lives rent free". A part whose code is an aggregate halts; the total must be the codelist's `IsTotal` code.
- **The geography type.** Every CSV row's `GEOGRAPHY_TYPE` must be exactly "local authorities: district / unitary (as of April 2023)" (`TYPE424`); `DATE_NAME` is the census year; `RECORD_COUNT` equals the rows read and `RECORD_OFFSET` runs 0 to n-1 (a truncated reply halts); each English authority has the nine categories exactly once.
- **The content hash** (`lad24cd` and the nine counts) decides "unchanged" and is what the ledger records, because the CSV and definition bytes are API output.

The held CSV, `data/raw/s3b_tenure/NM_2072_1_TYPE424_2026-10-10.csv` (2,862 rows: 318 authorities x 9, of which 296 are English and 22 Welsh), has bytes sha256 starting 80b690076f2d9203.

## Blanks and zeros (rule 1)

Every cell must be an integer written as digits; a blank or text halts and is never read as 0. The total is **the publisher's own**: the eight parts must sum to it on every authority or the load halts, and the loader never assigns the total (an AST test fails if it ever does). There are no NULLs and no zero counts in the table. The old n8n code took each cell as `obs[...] || 0` (a missing value would have become 0) and built `total_households` from the eight parts; no cell was missing, and the parts equal the publisher's total on all 296 authorities, so no stored value is wrong because of either. The re-basing (below) was wrong.

## Geography (rule 4)

Declared `old` in `scripts/geography.py`: for `TYPE424` NOMIS returns Barnsley and Sheffield as E08000016 and E08000019 (9 rows each), never E08000038 or E08000039. England (E06 to E09) is stored; Wales (W06) is read and ignored; any other code halts. Codes resolve through `geography.resolve('3b', ...)` and each canonical code must be in `la_boundaries`.

**Which boundaries.** The geography type is named "as of April 2023", so the four unitary authorities created that month are on their own codes: Cumberland, Westmorland and Furness, Somerset and North Yorkshire. A type on boundaries before April 2023 would give their predecessor districts, and the n8n workflow, which re-based the predecessors itself, understated Cumberland, Westmorland and Furness and Somerset (by 19,404, 31,259 and 75,940 households) and overstated North Yorkshire by 4 (`docs/decisions/2026-08-20-s3b-tenure-rebasing-error.md`). On 2026-08-20 those four rows were reloaded from NOMIS `NM_2072_1` on their current codes by direct SQL; the loader now reads the same geography type for all 296.

## Editions and revisions

An edition is what one NOMIS reply says about its census: per authority the nine published counts. Edition 1 is the table as held (published 2026-08-20, the latest load date), proved against the held reply: 296 authorities x 9 = 2,664 counts, **0 differences**. Today's reply (2026-10-11) and the extract of 2026-08-20 (`scripts/verify/src/ts054_current.json`) were also compared: 0 differences.

No revision has been seen. A later LastUpdated with the same content is `unchanged` (recorded in the ledger). Census counts are not expected to change, so a later LastUpdated with different content, or the same LastUpdated with different content, stops the load unless `--accept-reissue YEAR`; an accepted reissue is the next edition and reaches the live table only through `refresh-latest`. An earlier LastUpdated halts unless `--allow-older-file`; a reissue that drops or adds an authority is PARTIAL and no flag releases it. The registry has `revises_back_series` false.

**Another census** (2031, say) must be declared in `DATASETS` deliberately, with the evidence of its own definition; until then its definition halts. Once declared it is stored as editions only and never enters the live table through a load (`EditionSpec.live_single_period`; a census other than 2021 into an empty live table is REJECTED, whether it is new or already held as editions only: with the live table empty, a load inserts census 2021 and nothing else; this was tightened on 2026-10-11, when a held other census could have been re-inserted into an emptied table). `census_year` has no CHECK in the live table, so "one census in live" is held by the loader and by gate 3.

**`source`.** The live `source` column keeps its two held variants: "ONS Census 2021 TS054 Tenure, Nomis NM_2072_1, Census Day 21 March 2021" on 292 rows (loaded 2026-04-01) and "ONS Census 2021 TS054 Tenure, Nomis NM_2072_1, 2023 local authority boundaries" on the 4 rows reloaded on 2026-08-20. They are provenance, never compared, and a refresh writes `source` only on the rows it changes.

## How to run

Run from `ONS_Population_Estimates`; see the "Reference data" section of `docs/QUARTERLY_REFRESH.md`.

```bash
python scripts/s3b_tenure_editions.py status
python scripts/s3b_tenure_editions.py load            # preview; downloads the definition and the CSV
python scripts/s3b_tenure_editions.py load --commit
python scripts/s3b_tenure_editions.py refresh-latest   # preview; --commit applies an accepted reissue
python scripts/s3b_tenure_editions_verify.py
```

Other commands: `ddl` (already run), `restore-edition YEAR N`, and the one-off `migrate-legacy --file CSV --def JSON` (already run). `load` takes `--file CSV --def JSON`, `--recheck YEAR`, `--allow-older-file` and `--accept-reissue YEAR`. Every writing command previews unless `--commit` (or `--simulate`, which rolls back).

## Known traps

- **Taking an aggregate code as a category.** 1001 to 1004, 9996 and 9997 are the publisher's derived aggregates; look the categories up by name.
- **Using a geography type on other boundaries.** The four 2023 unitaries then come out as their predecessors.
- **Building the total from the parts.** Store the publisher's total and check the parts against it.
- **Treating the stored social and private totals as published.** The database generates them.
- **Hashing the files.** The CSV and definition are API output; the content hash is the identity.
- **Reading the two `source` variants as two releases.** Both labels name NM_2072_1, and the counts equal NM_2072_1; the 2026-04-01 label is the n8n workflow's, whose fetch node calls the ONS beta API (see History).
