# Publish the map without Jekyll, 2026-08-20

GitHub Pages ran every Markdown file in this repository through Jekyll. On
2026-08-20 that broke publication outright:

```
Error: Liquid syntax error (line 62): Variable '{{$now.plus({days: 7}'
was not properly terminated with regexp: /\}\}/
in n8n/n8n-expression-syntax/SKILL.md
```

n8n's expression syntax and Liquid's template syntax are both `{{ ... }}`.
Liquid tried to evaluate an n8n example as a template, failed, and the build
job died in 23 seconds. `deploy` was skipped, so the site kept serving the
16 August build and the demand map stayed on run 17 even though main was
correct.

Eight `SKILL.md` files carrying that syntax entered in `8a4b2bb`, the commit
that folded the second checkout into this one. No such file existed at the last
successful build, so publication had been broken since that commit and nothing
said so: `git push` succeeded, and the Pages **API kept reporting `building`**
long after the Actions run had already failed. Reading the API alone gives the
impression of a stalled queue rather than a failure.

**Decision: add `.nojekyll`.** The published site is `index.html` plus JSON and
GeoJSON under `data/`. There is no `_config.yml`, no `Gemfile`, no layouts and
no Markdown that is meant to be rendered into pages. Jekyll was doing nothing
for us and was processing 204 Markdown files on every deploy. `.nojekyll` makes
Pages publish the tree as-is.

This also removes the whole class of failure rather than the instance. Excluding
`n8n/` in a `_config.yml` would fix today's error and leave the next document
containing `{{`, `{%` or Liquid-like syntax free to break publication again.

**Check the Actions run, not the Pages API, when a deploy does not appear.**
`/repos/{owner}/{repo}/pages/builds/latest` reported `status: building` with
`duration: 0` for over twenty minutes on a run that had already failed.
